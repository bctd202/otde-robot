# Architecture

The React/Vite client reads cached FastAPI REST responses; a heartbeat WebSocket remains available for a future push transport. A server-owned APScheduler job checks for each newly completed one-minute candle, scans once, and persists the complete result. The browser polls that cache and cannot multiply provider scans. FastAPI delegates all quotes, candles, chains, and feed metadata through a provider interface. `MockMarketDataProvider` is deterministic and explicitly reports `mode=mock`; the Tradier adapter is read-only, fails closed, and cannot place orders.

The setup service computes VWAP, opening range, swings, liquidity levels, structured candidates, and separately ranked lottery candidates. No LLM participates in calculations. The signal engine advances durable WATCH/BUY/terminal lifecycles, stores alert events, and evaluates open paper/research outcomes. Paper entry reruns the complete setup and exact contract selection on the server before persisting. SQLAlchemy persists scans, lifecycle state, alerts, market data, setups, paper entities, outcomes, reports, settings, and quality events. Alembic owns schema initialization; SQLite is the local default.

The seed command rebuilds a deterministic demo dataset. React renders provider, engine health, lifecycle validity, account safety, and alert history before secondary market context, and visually isolates the Lottery Lab.
